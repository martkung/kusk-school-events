# Optional attendee signature at check-in

At the check-in station: scan/enter the pass, verify the applicant name, optionally select เก็บลายเซ็นผู้เข้าร่วม, let the attendee sign using a finger/stylus/mouse, acknowledge attendance/evidence use, then save. The same station keeps the option for the next attendee, but the drawing, acknowledgement and capture ID are reset for each person. Clear/redraw is available. Failed saves retain the in-memory drawing for retry; no drawing is placed in browser storage. Existing QR and ordinary checkin remain supported.

Saving is limited to active assigned checkin staff and Admin, rechecked before upload and in the final Firestore transaction; approved LINE Admin authorization is revalidated. The event must be open for checkin and the application approved. Appending a first signature after ordinary checkin preserves the original checkin actor/time. The displayed signer name must still match current application data. Recorded signatures cannot be overwritten via this feature. The attendee acknowledgment text for attendance-v1: ข้าพเจ้ายืนยันการเข้าร่วมกิจกรรม และรับทราบว่าจะเก็บลายเซ็นนี้ประกอบหลักฐานการเข้าร่วมและการเบิกจ่ายของกิจกรรม.

PNG data is decoded with CRC checking, dimension/byte/ink bounds, then reencoded server-side. Storage path is generated by the server: schoolEventSignatures/eventId/applicationId/captureId.png. Conditional create prevents file overwrite. A dedicated Storage client disables SDK automatic retries and upload requests have a 20-second timeout, bounded below the upload lease; users explicitly retry with the same capture ID. Storage Rules deny all direct signature access, including client Admin; no download token/public URL is generated. Authorized callable view (assigned checkin/report/review role or Admin) verifies the recorded generation and SHA256, then rechecks authorization. Images are never embedded in Firestore or logs. Firestore keeps path, generation, digest, server timestamp, recorder UID, signer-name snapshot, acknowledgment version and capture ID, plus an audit event. This release covers capture/view only, not reimbursement document generation.

Upload leases are private event descendants. The upload function has a 60-second timeout and a 180-second lease; purge waits for live leases before deleting both poster and signature prefixes. Final commit rejects purging/deleted/closed events, revoked staff and changed signer names. Failed/losing uploads are cleaned; timed-out upload residues are swept during event purge after the lease expires. Completed evidence is retained on soft trash and removed on permanent event purge under the existing backup/retention policies. No real signature or production checkin was created for verification.

Applicant detail popup displays the existing private signature and recorded time under contact details. Reviewers gain read-only evidence access for their assigned event; capture remains checkin/Admin only. Stale/closed-popup responses cannot append images, and the image is removed with the popup content on close.
