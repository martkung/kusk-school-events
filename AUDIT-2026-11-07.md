# Stability review — 2026-11-07

Scope: the active `school-events` application, its browser modules, Cloud Functions, Firestore and Storage rules. The dormant parent application was not deployed.

## Corrections

- Removed a second, one-shot home catalog renderer which replaced the live subscription's DOM and prevented subsequent visible updates.
- Added bounded automatic retry/backoff for failed live refreshes, without concurrent requests or retries after disposal.
- Isolated staff requests and private dialogs across account changes (including A → B → A), navigation and selected-event changes.
- Prevented native profile-form submission while loading, preserved typed input, and ignored late saves from a previous account.
- Added stale-edit detection to the event editor; validated malformed poster URLs and aligned enrollment/QR event-ID limits.
- Rechecked approved LINE administrator configuration inside write transactions and in database/storage rules. Removing approval denies staff access while preserving the applicant's own access.
- Made poster upload rules use the catalog's deletion/purge lock within Storage's cross-service lookup limit; missing catalog records fail closed.
- Hardened PNG signature validation against repeated headers, animation chunks and trailing payloads before decoding.
- Added owned upload leases and cleanup guards so competing/retried signature submissions cannot remove another invocation's upload. Limited signature/purge service concurrency.
- Rechecked event availability around applicant-list queries.

## Validation

- 203 automated tests passed (`node --test *.test.mjs functions/*.test.cjs`). Includes live-catalog updates, account races, profile typing/saves, signature races and stale edits.
- 22 Firestore and 27 Storage synthetic Rules API cases passed. These use mocked resources, not real applicant mutations.
- Syntax/local-import checks passed across 99 source/script files.
- Production dependency audits reported zero known vulnerabilities for Functions and browser tooling dependencies at review time.
- No real applicant was enrolled, deleted, checked in or signed as a test. No personal-data export was created.

## Limits

Automated checks do not establish that all defects are absent. This review did not include a physical mobile device/camera, printed-paper layout, sustained production load or forced process termination. Storage cleanup remains best-effort if a process is terminated; the existing purge flow handles remaining files after leases expire. Google token/custom-claim lifetime behavior was not redesigned.

Storage cross-service rule limits: https://firebase.google.com/docs/storage/security/rules-conditions
